## Design Specificity Verdict

**LLM assessment**: Emphatically authored for this exact product, not a generic map template. Indonesian-first copy throughout, WITA-specific clock anchor, hardcoded Palu/Donggala service-area bounding boxes, corridor colors mapped to the real operator's city codes, a TJ Transjakarta interaction model adapted (not copied) for a two-city BRT system, and code comments documenting a real correction cycle (removing a false "buses stop at 18:00" claim once real operating hours were learned). That correction-cycle evidence is the strongest signal — this team iterates against real operational behavior, not template assumptions.

**Deterministic scan**: Static CLI scan of `apps/web/src` (85 files) found 3 findings across 2 rules: `layout-transition` (BottomSheet.vue:44, NearbyHaltePanel.vue:132 — animating `height`/`max-height` directly instead of `transform`) and `overused-font` (RideShareCard.vue:174, redundant Inter declaration). Live browser-overlay passes across 5 view/viewport combinations (Home desktop/mobile, main map desktop/mobile, map-export) surfaced far more: contrast failures down to 2.3:1, undersized text down to 8px, nested cards, cramped padding, a persistent pulsing-dot loading indicator, and flat type hierarchy. No false positives were found in the CLI scan; several overlay findings are likely the same underlying issue recurring across DOM nodes (noted under Minor Observations) rather than distinct defects.

**Visual overlays**: Not left running in the browser — the isolated detector sub-agent stopped its live-server and removed its session before this report was written. Findings below are drawn from its structured output, not a live in-browser overlay you can currently view.

## Overall Impression

This is a genuinely well-considered product for its domain — the corridor-color system, ETA-quality signaling, and honest operating-status copy show a team designing against real operational truth, not a template. The single biggest opportunity is that the app has clearly designed for *degraded* data (stale buses, slow ETAs) but not for *absent* data — a socket connection that never establishes leaves the user in an infinite, unexplained loading state, which is the worst possible experience for someone anxiously checking "is my bus coming." A close second: several small execution gaps (contrast, undersized map-view text, a first-load onboarding tour that fires before the user has even picked a city) undercut the otherwise strong domain-specific design work.

## What's Working

1. **Honest operating-status copy.** The team removed a false "buses don't run 06:00–18:00" claim once they learned real service extends later — rare discipline for a transit product to prefer "we don't know" over a confident-but-wrong claim.
2. **ETA-quality signal, not just a number.** Green/orange/gray + text label + an always-adjacent guide teaches users to calibrate trust in an estimate, satisfying "don't convey info by color alone" rather than presenting a bare "5 min" as gospel.
3. **Deep-linkable everything.** A copy-link action on bus/halte/corridor/trip lets a commuter text a specific stop or bus to someone else — a real, domain-specific utility, not generic share-button theater.

## Priority Issues

**[P0] No terminal state for a socket connection that never establishes**
- **Why it matters**: `stores/socket.ts` only flips state to "offline" inside the `disconnect` handler — i.e., after a prior successful connect. There's no `connect_error`/attempt-cap path, so if the initial handshake never completes, the UI sits on "Memuat data bus…" with a pulsing dot implying progress, forever. Live-verified with ~40 failed reconnects and no state change. This is also very likely what the detector's persistent `.ck-splash__pulse` finding (present on every single view/viewport pass, including views where data should have loaded) is actually reporting.
- **Fix**: Add a timeout/`connect_error` handler that reaches a genuine "unreachable, tap to retry" state.
- **Suggested command**: `/impeccable harden`

**[P0] Onboarding tour auto-fires on Home, degraded to one orphaned step**
- **Why it matters**: Tour step filtering is per-selector, not per-page; since the top bar's settings button renders globally, Home always matches exactly one step. Live-verified: first load opens a coach-mark about *audio announcements* — a secondary feature — dimming the hero and both city cards before the user has picked a city. This directly contradicts an in-code comment claiming the tour "skips silently... on the home view."
- **Fix**: Gate tour launch to the city route, or drop tours whose surviving step-count falls below a minimum.
- **Suggested command**: `/impeccable onboard`

**[P0] Severe contrast failure on Home (2.3:1, more than half the WCAG floor)**
- **Why it matters**: Detector-measured `#a8a29e` on `#f7f7f4` = 2.3:1 against the required 4.5:1, on both desktop and mobile Home passes. This isn't a near-miss like the stone-500 finding below — it's a genuine accessibility blocker, and in outdoor Sulawesi sun glare it's a real legibility risk, not theoretical.
- **Fix**: Identify the exact element(s) using this pairing (likely a lighter secondary/placeholder tone) and bring it to at least 4.5:1.
- **Suggested command**: `/impeccable polish`

**[P1] Mobile shows a strictly worse error message than desktop for the identical failure**
- **Why it matters**: The desktop sidebar reads the error state and shows "Gagal memuat data · 500 Internal Server Error." The mobile routes panel — the primary surface for this mobile-first PWA — never reads that same ref, so on identical failure it falls through to generic empty-state copy ("no results"), which reads as "there are no routes" rather than "we couldn't reach the server."
- **Fix**: Thread the shared error ref into the mobile Rute/Halte tabs.
- **Suggested command**: `/impeccable harden`

**[P1] TopBar city-switcher fallback label overflows its circular button**
- **Why it matters**: When city icon metadata is falsy, the fallback renders the full city name unclamped inside a 36×36px circle. Live-verified at both desktop and mobile: text wraps to two lines, spills out of the circle, and overlaps the wordmark and adjacent icons — the very first thing a user sees whenever city metadata loads slowly, not just under a broken backend.
- **Fix**: Clip to a two-letter monogram or cap font-size/width on the fallback state.
- **Suggested command**: `/impeccable polish`

**[P1] Systemic undersized text on the main map/tracking view**
- **Why it matters**: Detector-verified 8–10px text across both desktop and mobile: corridor name labels, legend text, speed units ("km/jam" at 9px), version tag, and legend swatch labels ("K1" at 8px) — all below an 11px floor, on the app's core screen.
- **Fix**: Raise these to at least 11px; audit the map-view type scale as a set rather than patching individually.
- **Suggested command**: `/impeccable typeset`

**[P1] Near-miss contrast failure on stone-500/paper-background pairing, confirmed independently by both assessments**
- **Why it matters**: `--color-bnc-stone-500` (#78716C) on paper (#F7F7F4) computes to ≈4.47:1, just under the 4.5:1 AA threshold, used as the default color for meta-labels app-wide (section eyebrows, timestamps, stat labels) at 10–11px. The team already fixed the analogous dark-mode contrast bug; this is the light-mode counterpart they missed.
- **Fix**: Darken the token slightly to clear 4.5:1.
- **Suggested command**: `/impeccable polish`

**[P2] Touch targets sit at 32–36px across nearly every icon control**
- **Why it matters**: Map floating buttons, TopBar actions, and trip-planner GPS/tap-on-map buttons clear the web-only 24px WCAG minimum but fall short of the 44pt/48dp mobile-app target size a "used one-handed on the street" PWA should aim for.
- **Fix**: Bump primary controls to ≥44px on touch viewports.
- **Suggested command**: `/impeccable polish`

**[P2] Nested cards and cramped padding on the map view**
- **Why it matters**: Detector-flagged "card inside card" pattern (x2, desktop+mobile) and two containers with content flush against the background with no inset — adds visual noise/hierarchy confusion to the app's busiest screen.
- **Fix**: Flatten redundant card wrapping; add consistent inset padding.
- **Suggested command**: `/impeccable layout`

**[P2] Layout-transition anti-pattern (confirmed by both static scan and live overlay)**
- **Why it matters**: `BottomSheet.vue:44` and `NearbyHaltePanel.vue:132` animate `height`/`max-height` directly rather than `transform`, which is expensive to animate and causes jank — flagged independently by the static CLI scan and the live browser overlay.
- **Fix**: Switch to `transform`/`grid-template-rows` based expand-collapse animation.
- **Suggested command**: `/impeccable optimize`

**[P3] Flat type hierarchy on the map-export view**
- **Why it matters**: 6 font sizes (10–17px) compressed into only a 1.7:1 ratio — insufficient visual differentiation for a shareable export view.
- **Fix**: Widen the type scale for this view.
- **Suggested command**: `/impeccable typeset`

## Persona Red Flags

**Casey (Distracted Mobile User)**: Hits the socket P0 hardest — a 3-second glance at the phone while jogging to a stop, on flaky signal, returns an unexplained infinite spinner with no retry affordance. The 32px GPS/tap-on-map buttons in the trip planner are tight one-handed thumb targets, compounded by a short bottom-sheet peek height. Hits the TopBar overflow bug on literally her first glance at the header.

**Jordan (Confused First-Timer)**: Her very first interaction (per the live-verified onboarding-tour bug) is a coach-mark about *audio announcements* — a secondary feature — instead of anything explaining what a "koridor" is or how direction A/B works, which are the concepts she actually needs. The direction selector labels directions only by terminal name; nothing defines what "arah"/direction means for someone who's never used a BRT system. The corridor-spotlight model (dimming everything except the focused route) assumes she already knows which corridor she wants — a reasonable power-user default, a cold one for someone still exploring.

**Sam (Accessibility-Dependent)**: Carries both contrast failures (the 2.3:1 severe failure and the 4.47:1 near-miss on stone-500) at nearly every meta-label app-wide, mostly at 10–11px — well below the "large text" exception, and a real legibility risk in outdoor sun glare, not theoretical. The corridor-error paragraph has no `role="alert"`/`aria-live`, inconsistent with the app's otherwise good use of `role="status"` elsewhere. Compounded by the same 32px touch targets flagged for Casey — a double burden for limited fine motor control.

## Minor Observations

- `overused-font`: redundant Inter font-family declaration in RideShareCard.vue:174.
- Uppercase tracked-caps ("call-caps-body") styling on Home hero copy, flagged on both desktop and mobile passes.
- 11px body text on Home sits right at the floor.
- Stat tiles render a literal "0" during a backend outage rather than distinguishing "confirmed zero" from "unknown" — a subtle trust nuance during real incidents.
- The `ck-splash` pre-mount loading pattern (inline critical CSS, pre-paints dark mode before Vue mounts) is genuinely well-built — worth reusing elsewhere, not a criticism.
- Stale-bus visual treatment (grayscale + hatch + badge) is consistently applied across map marker, bus card, and halte card — a coherent multi-surface pattern worth protecting in future changes.
- Environment caveat: the local dev backend (`/api/cities*`, socket.io) returned 500s / never connected during this review, so neither assessment could observe a populated live map, bus markers, or the trip/bus-detail panel. All findings above are either code-read-verified or reproducible independent of backend state (contrast, text size, layout, the tour bug, the missing terminal socket state) — but a populated-state pass against a working backend is recommended before this critique is treated as complete.

## Questions to Consider
